# 清荷 v3 - 腾讯手游账号本地切换模块 - 需求文档

## 简介

一套运行于 Android 手机端的腾讯手游账号本地切换工具，提供 KSU/Magisk 模块和 MT 管理器 Shell 脚本两种使用形态。通过备份和替换游戏本地数据实现多账号快速切换。v3 版本聚焦 Web UI 全面升级，采用 HelloKitty 主题风格，简化游戏覆盖范围并优化交互流程。

## 术语表

- **系统（System）**：腾讯手游账号本地切换器"清荷"，包含 KSU/Magisk 模块和独立 Shell 脚本两种交付形态
- **Web UI**：通过手机浏览器访问的图形化管理界面，运行于设备本地端口 8848
- **账号（Account）**：一组游戏本地数据的备份存档，包含账号别名、游戏包名、数据文件集合
- **本机路径**：游戏在 `/data/data/<pkg>/` 下的标准数据目录路径
- **分身路径**：游戏双开/分身空间下的数据目录路径（如 `/data/user/999/<pkg>/` 或 `/data/user/10/<pkg>/`）
- **自动备份**：切换账号前系统自动触发的备份操作，无需用户干预
- **手动备份**：用户在 Web UI 中主动触发并自定义名称的备份操作
- **框选恢复**：用户在备份列表中勾选目标备份项后点击恢复按钮完成切换的操作模式

## 需求

### 需求 1：游戏覆盖范围

**用户故事：** 作为手游玩家，我希望工具预制支持我常玩的 5 款腾讯手游，以便快速进行账号管理。

#### 验收标准

1. 系统 SHALL 预置 5 款腾讯手游的配置信息：王者荣耀、和平精英、三角洲行动、无畏契约、CF 手游
2. 系统 SHALL 在 games.ini 中仅保留上述 5 款游戏的包名、数据路径和备份子目录配置
3. 系统 SHALL 移除旧版本中不在 5 款范围内的游戏配置（QQ 飞车、使命召唤手游、金铲铲之战、英雄联盟手游、火影忍者、天涯明月刀）

---

### 需求 2：游戏自动检测与超时回退

**用户故事：** 作为手游玩家，我希望 Web UI 能自动识别我手机上已安装的腾讯游戏，若识别超时也能快速进入手动选择。

#### 验收标准

1. WHEN Web UI 首次加载，系统 SHALL 自动扫描设备上已安装的腾讯手游（通过 `pm list packages`），并以列表展示
2. WHILE 自动检测进行中，系统 SHALL 展示加载动画和检测状态提示
3. IF 自动检测超过 10 秒仍未返回结果，系统 SHALL 终止自动检测并展示预置的 5 款游戏选项供用户手动选择
4. WHEN 超时回退后，系统 SHALL 在游戏列表页直接展示 5 款预置游戏卡片供用户点击，同时展示提示信息说明自动检测超时

---

### 需求 3：路径选择（本机路径与分身路径）

**用户故事：** 作为双开用户，我希望在选定游戏后能看到本机路径和分身路径的选项，以便管理不同空间下的游戏账号。

#### 验收标准

1. WHEN 用户点击一个游戏进入详情，系统 SHALL 以并排卡片形式展示"本机路径"和"分身路径"选项，每个卡片显示路径图标、路径信息和存储空间大小
2. WHEN 加载游戏详情时，系统 SHALL 自动检测该游戏是否存在分身路径（通过扫描 `/data/user/` 下非 0 的 user ID 目录）
3. IF 检测到分身路径存在，系统 SHALL 同时展示"本机路径"和"分身路径"两张并排卡片，用户点击选中高亮
4. IF 未检测到分身路径，系统 SHALL 仅展示"本机路径"一张卡片
5. 系统 SHALL 在每个路径卡片中显示对应数据目录的存储空间大小

---

### 需求 4：备份功能（自动备份与手动自定义备份）

**用户故事：** 作为手游玩家，我希望既能一键快速备份，也能手动命名备份以便区分不同场景。

#### 验收标准

1. WHEN 用户确认游戏和路径后进入第二层级界面，系统 SHALL 展示"自动备份"和"自定义备份"两个选项
2. WHEN 用户点击"自动备份"按钮，系统 SHALL 自动生成备份名称（格式为"自动备份-YYYYMMDD-HHmmss"）并执行备份操作
3. WHEN 用户点击"自定义备份"按钮，系统 SHALL 弹出文本输入框供用户输入自定义名称
4. IF 自定义备份名称已存在，系统 SHALL 提示用户名称冲突并要求修改或确认覆盖
5. WHEN 备份完成，系统 SHALL 展示备份成功提示并自动刷新备份列表

---

### 需求 5：框选式恢复

**用户故事：** 作为手游玩家，我希望在恢复界面中勾选目标备份并一键恢复，操作直观且不易误触。

#### 验收标准

1. WHEN 用户进入恢复界面，系统 SHALL 以卡片列表形式展示当前游戏路径下的所有备份条目
2. 系统 SHALL 在每个备份条目左侧提供复选框，支持用户点击勾选
3. 系统 SHALL 支持多选复选框，但恢复操作仅限单选——当用户勾选第二个条目时自动取消第一个的勾选
4. WHEN 用户勾选一个备份条目并点击"恢复"按钮，系统 SHALL 弹出确认对话框，展示目标备份的详细信息（备份名称、创建时间、数据大小、所属游戏）以及切换前自动备份的提醒
5. WHEN 恢复操作确认后，系统 SHALL 先在后台自动备份当前游戏数据，再将目标备份数据覆盖到游戏目录
6. IF 游戏进程正在运行，系统 SHALL 在恢复前检测并提示用户关闭游戏

---

### 需求 6：Web UI 自动超时机制

**用户故事：** 作为模块管理员，我希望 Web 服务能在设备闲置时自动关闭，减少意外暴露风险。

#### 验收标准

1. 系统 SHALL 在 Web 服务启动时启动一个后台计时器（默认 120 秒）
2. WHILE Web UI 有 HTTP 请求活动，系统 SHALL 重置计时器
3. IF 计时器到期（120 秒无请求），系统 SHALL 自动关闭 Web 服务进程
4. WHEN Web 服务即将超时关闭（剩余 10 秒），系统 SHALL 在 UI 底部展示倒计时提示

---

### 需求 7：HelloKitty 主题 UI

**用户故事：** 作为手游玩家，我希望 UI 界面采用 HelloKitty 风格元素，比普通工具界面更有趣味性。

#### 验收标准

1. 系统 SHALL 以粉色系（#FF6B9D、#FF85AB、#FFB8CC）为主色调，搭配白色作为辅色
2. 系统 SHALL 在页面装饰中使用 HelloKitty 标志性元素（蝴蝶结、猫耳轮廓、粉色爱心点缀）
3. 系统 SHALL 使用圆角（border-radius 12-16px）和柔和阴影（box-shadow 粉色系）的卡片式布局
4. 系统 SHALL 在顶部 Header 区域展示蝴蝶结装饰图标和应用标题
5. 系统 SHALL 在页面过渡和按钮交互中使用柔和的动画效果
6. 系统 SHALL 使用粉色渐变背景（#FFF0F5 到 #FFD6E0）

---

### 需求 8：KSU/Magisk 模块 + MT 管理器脚本双形态

**用户故事：** 作为不同使用习惯的用户，我希望通过 KSU/Magisk 模块或 MT 管理器直接运行脚本两种方式使用工具。

#### 验收标准

1. 系统 SHALL 提供标准 Magisk/KSU 模块 zip 包，安装后在 `/data/adb/modules/qinghe/` 部署脚本和 Web UI
2. 系统 SHALL 模块安装后将 `qh` 命令注册到 `/system/bin/`，支持终端直接调用
3. 系统 SHALL 提供独立的 `.sh` 脚本入口文件，可在 MT 管理器中直接点击执行命令行模式
4. 系统 SHALL 在模块卸载时询问用户是否保留已备份的账号存档数据
5. 系统 SHALL 在模块的 `web/` 目录中包含完整的 Web UI 前端资源（HTML/CSS/JS）

---

### 需求 9：后台 API 兼容

**用户故事：** 作为系统集成方，我希望新的 Web UI 与现有后端 API 保持兼容，避免推倒重来。

#### 验收标准

1. 系统 SHALL 沿用现有 `/cgi-bin/api` 的 CGI 路由模式
2. 系统 SHALL 保持现有 API 端点（detect、accounts、backup、restore、delete、status）的请求格式和返回结构
3. 系统 SHALL 在 detect API 返回中新增分身路径检测字段 `clone_path` 和 `clone_installed` 布尔值
4. 系统 SHALL 在 backup API 中新增 `mode` 参数（`auto` / `custom`）以区分自动备份和手动备份
5. 系统 SHALL 在恢复 API 返回中新增自动备份确认状态字段 `auto_backup_done`
